# 모델 발표 예상 질문과 답변

## SLIDE 4. 모델과 데이터

### 1. 이 모델을 한 문장으로 설명하면 무엇인가요?

서울 아파트 단지·평형의 KB 매매시세 상승률을 예측하기 위해, 예측 개월 수를 입력받는 하나의 LightGBM으로 기본 예측을 만들고 최근 검증 데이터에서 확인한 단지·평형별 반복 오차를 보정한 모델이다.

### 2. 왜 분류가 아니라 회귀 문제인가요?

사용자는 가격이 오를지 여부만이 아니라 얼마나 오를지를 알아야 대출과 자기자금 계획을 세울 수 있다. 따라서 상승·하락 여부를 맞히는 분류가 아니라 미래 KB 매매시세의 상승률을 연속값으로 예측하는 회귀 문제로 정의했다.

### 3. Multi-Horizon이라는 말은 일반적으로 사용하는 용어인가요?

여러 미래 시점의 값을 예측하는 문제를 `multi-horizon forecasting`이라고 부르는 것은 일반적이다. 다만 우리 모델은 여러 상승률을 하나의 벡터로 동시에 출력하는 multi-output 모델은 아니다. `horizon_months`를 입력해 같은 모델을 기간별로 호출하는 **예측기간 조건부 단일 모델**이다.

### 4. 슬라이드의 “1개월~61개월”이 예측기간인가요?

아니다. 61개월은 2021년 6월부터 2026년 6월까지의 월별 관측 기간을 뜻한다. 학습 데이터의 horizon은 12·24·36·48·60개월이고, 서비스 화면은 12·36·60개월, 즉 1·3·5년을 제공한다. 발표 전 슬라이드 문구를 반드시 구분해 수정해야 한다.

### 5. 왜 LightGBM을 사용했나요?

가격, 면적, 연식, 세대수, 거리, 시설 수처럼 서로 형태가 다른 정형 feature가 중심이기 때문이다. LightGBM은 비선형 관계와 변수 간 상호작용을 다루기 좋고 학습과 inference가 빠르다. 반복 실험, feature 중요도 분석, Streamlit 서비스 연결도 비교적 간단하다.

LightGBM이 모든 모델보다 항상 우수하다는 뜻은 아니다. 이번 프로젝트의 데이터 형태와 일정, 설명가능성, 운영 편의성을 고려한 엔지니어링 선택이다.

### 6. 딥러닝이나 LSTM은 왜 사용하지 않았나요?

단지별 시계열이 2021년 6월 이후로 짧고, 특히 60개월은 검증 가능한 실현값이 충분하지 않다. 긴 시계열을 전제로 하는 복잡한 모델보다 단지 메타·입지·가격·예측기간을 함께 사용하는 tabular regression이 현재 데이터에 더 자연스럽다고 판단했다.

### 7. 데이터가 약 203만 건이라는 것은 무슨 뜻인가요?

아파트가 203만 개라는 뜻이 아니다. 하나의 행은 `단지·평형·기준월·예측기간` 조합이다. 12·24·36·48·60개월 라벨을 길게 쌓은 multi-horizon 모델링 데이터가 2,026,935행이다.

- 고유 단지: 6,297개
- 고유 단지·평형 조합: 27,902개
- 원천 월별 KB 시계열: 2,657,585행
- 서울 소재 학교·역·병원: 1,785개
- 최종 base model 활성 feature: 55개

서로 단위가 다른 수치를 모두 더해 “총 데이터 수”라고 표현하지 않는다.

### 8. 어떤 feature를 사용했나요?

다섯 묶음으로 설명할 수 있다.

1. 예측기간: `horizon_months`
2. KB 시장정보: 매매시세, 전세시세, 전세가율, 시세갭
3. 단지·평형 정보: 구, 면적, 연식, 세대수, 용적률, 건폐율
4. 주변 주요 시설: 역·학교·병원까지의 거리와 반경별 시설 수
5. 파생 feature: 평당가, 단지 내 면적·가격 순위, 구 대비 가격 프리미엄

### 9. POI는 무엇이며 성능을 많이 높였나요?

POI는 `Point of Interest`, 즉 역·학교·병원 같은 주변 주요 시설이다. 각 아파트와의 직선거리와 반경 내 시설 수를 feature로 만들었다.

초기 ver3에서 POI만 추가했을 때 MAE 개선은 크지 않았다. 따라서 “입지 feature가 최종 성능을 크게 올렸다”고 말하면 안 된다. 부동산 맥락에서 설명 가능한 정보를 제공하지만, 큰 성능 개선은 이후 residual 보정에서 나왔다.

### 10. 실거래 가격과 거래량은 왜 최종 feature에서 제외했나요?

일부 단지·평형은 최근 실거래가 없고 집계 지연과 결측이 크다. 학습에서는 도움이 되더라도 서비스 시점에 동일한 품질로 입력된다고 보장하기 어렵다. 최종 모델은 언제든 안정적으로 계산 가능한 KB 시세와 단지·입지 feature를 우선했다.

### 11. 단지 ID와 평형 ID도 LightGBM feature인가요?

아니다. `complex_id`와 `apt_size_id`는 단지·평형을 선택하고 residual 보정값을 찾는 식별 키다. base LightGBM에는 ID 자체가 입력되지 않는다. 실제 면적, 연식, 가격, 입지 등의 설명 변수가 입력된다.

## SLIDE 4-1. 추론과 보정

### 12. 1년·3년·5년 모델을 따로 만들지 않은 이유는 무엇인가요?

기간별 전용 모델은 특정 기간에서 조금 더 좋을 수 있지만 데이터와 모델 파일, 운영 코드를 기간별로 관리해야 한다. 하나의 모델에 `horizon_months`를 넣으면 여러 기간의 데이터를 함께 활용하고 동일한 inference 함수로 운영할 수 있다. 이번 서비스는 기간별 최고 성능보다 일관된 1·3·5년 인터페이스를 우선했다.

### 13. 세 기간을 모델이 한 번에 동시에 출력하나요?

아니다. 서비스 요청 한 번으로 세 결과를 묶어 반환하지만 내부에서는 같은 LightGBM에 12, 36, 60을 각각 입력해 기간별로 예측한다. 따라서 `single multi-horizon model`은 맞지만 `single-pass multi-output model`은 아니다.

### 14. Residual 보정을 쉽게 설명하면 무엇인가요?

**기본 예측에 과거의 반복 오차를 보완하는 과정**이다. 예를 들어 어떤 단지·평형을 최근 검증 기간에 계속 2%p 낮게 예측했다면, 그 경향이 다음 기간에도 일부 이어질 수 있다고 보고 기본 예측을 보정한다.

### 15. 데이터가 적은 평형은 어떻게 보정하나요?

한두 건의 오차를 그대로 믿으면 과도한 보정이 될 수 있다. 데이터가 적을수록 다음과 같이 더 넓은 집단의 평균 오차를 참고한다.

```text
같은 단지·평형·예측기간
→ 같은 단지·예측기간
→ 같은 구·비슷한 면적
→ 같은 예측기간 전체
→ 전체 평균
```

이것이 계층형 shrinkage와 fallback을 사용한 이유다.

### 16. 보정값은 사용자가 요청할 때 실시간으로 학습하나요?

아니다. 최근 3개 validation 월의 residual로 보정값을 미리 계산해 CSV에 저장한다. 추론 시에는 해당 단지·평형·기간의 offset을 조회해 base 예측값에 더한다. 데이터가 갱신되면 학습·보정 pipeline을 다시 실행해 offset 파일도 갱신해야 한다.

### 17. Residual 보정은 test 데이터를 본 leakage 아닌가요?

최종 ver16 보정값은 test label이 아니라 validation 기간의 residual로 만든다. 또한 validation rolling holdout에서도 같은 설정의 개선 방향을 확인했다.

test 결과에 맞춰 보정 비율을 선택했던 ver14는 안정성 검증을 통과하지 못해 최종 모델에서 제외했다. 이 과정을 통해 test 과적합 위험을 줄였다.

### 18. P80과 P90은 신뢰구간인가요?

정식 통계적 신뢰구간은 아니다. 과거 test 절대오차를 작은 순서로 놓았을 때 80% 지점과 90% 지점의 값이다. 전체 test 기준 P80은 8.6336%p, P90은 13.6911%p다.

예상 상승률이 10%이고 적용되는 P80 오차가 8%p라면 약 2%~18%를 과거 오차 기준 참고 범위로 보여줄 수 있다. “미래 값이 80% 확률로 반드시 이 안에 있다”고 해석하면 안 된다.

### 19. Confidence는 어떻게 결정하나요?

예측기간과 적용된 보정 단계에 따라 보수적으로 표시한다. 단지·평형 또는 단지 수준의 구체적인 보정값을 쓸 수 있는지, 과거 오차 범위가 어느 정도인지가 중요하다. 36개월과 60개월은 현재 서비스 코드에서 낮은 신뢰도로 처리하며, 특히 60개월은 global fallback을 사용한다.

### 20. 60개월 예측은 믿을 수 있나요?

예측값은 반환할 수 있지만 공식적인 성능 수치로 강하게 주장하면 안 된다. 데이터가 2021년 6월부터 시작해 60개월 뒤 실현값이 충분히 쌓이지 않았기 때문이다. 서비스에서는 `low confidence`로 표시하고 의사결정의 보조 참고값으로만 사용한다.

## SLIDE 4-2. 성능과 모델 선택

### 21. MAE 5.0376은 어떻게 해석하나요?

평균적으로 예측 상승률이 실제 상승률과 약 5.0376%p 차이 났다는 뜻이다. 정확도가 95%라는 뜻도 아니고, 가격이 평균 5% 틀렸다는 뜻도 아니다. 상승률의 평균 절대오차다.

### 22. 그래프의 모든 버전을 동일 조건으로 직접 비교할 수 있나요?

완전히 그렇지는 않다. ver1·ver3은 초기 문제 정의, ver7d는 12개월 전용 모델이어서 최종 multi-horizon 모델과 평가 대상과 구조가 다르다. 이 구간은 탐색 과정의 milestone을 보여주는 참고 그래프다.

엄밀한 최종 개선 비교는 동일한 multi-horizon base 구조를 유지한 `ver9b → ver11 → ver12d → ver13 → ver16` 채택 경로로 설명해야 한다.

### 23. ver7d가 7.12인데 왜 8.23인 ver9b로 돌아갔나요?

ver7d는 12개월 전용이라 해당 기간에서는 강했지만 서비스가 요구하는 1·3·5년을 처리하지 못한다. ver9b는 단기 성능 일부를 양보하고 하나의 모델로 여러 기간을 처리하는 구조를 확정한 버전이다. 이후 residual 보정을 통해 최종 ver16에서 전체 multi-horizon MAE를 5.04%p까지 낮췄다.

### 24. 38.8% 개선은 어떻게 계산했나요?

동일한 multi-horizon 기준 모델 ver9b의 MAE 8.2285에서 최종 ver16의 5.0376으로 감소한 비율이다.

```text
(8.2285 - 5.0376) / 8.2285 × 100 ≈ 38.8%
```

구 단위 ver1이나 12개월 전용 ver7d 대비 수치가 아니다.

### 25. ver14가 더 좋아 보이는데 왜 최종에서 제외했나요?

ver14의 test MAE는 5.3811로 ver13보다 낮았다. 하지만 보정 비율이 test 결과를 보면서 선택돼 test에 맞춘 결정일 위험이 있었다. 별도의 validation rolling holdout에서는 개선이 안정적으로 재현되지 않았기 때문에 최종 채택하지 않았다.

### 26. R²와 Spearman은 어떻게 해석하나요?

- R² 0.7150: test 상승률 변동의 약 71.5%를 모델 예측이 설명했다는 회귀 지표다.
- Spearman 0.8715: 예측 상승률의 상대적 순서와 실제 순서가 강하게 일치했다는 뜻이다.

둘 다 모델 신뢰도를 단독으로 보장하지 않는다. 개별 숫자 예측이 목적이므로 주 지표는 MAE이고, RMSE·P80·P90·Spearman은 보조 지표다.

### 27. 학습·검증·test는 어떻게 나눴나요?

각 horizon별 시간 순서를 유지했다. 마지막 5개월을 test, 그 직전 5개월을 validation으로 두고 그 이전 기간을 학습에 사용했다. 미래 데이터를 과거 예측에 섞는 누수를 막기 위한 시간 기반 분할이다. 60개월은 충분한 test 기간이 없어 공식 horizon별 test 평가에서 제외했다.

### 28. 이 성능은 실무적으로 사용할 수 있나요?

매수 여부를 자동 결정하거나 수익을 보장하는 수준은 아니다. 다만 특정 단지·평형의 기대 상승률과 과거 오차 범위를 대출·자금 분석과 함께 확인하는 의사결정 보조 지표로는 사용할 수 있다.

예측 대상도 실제 매매 수익률이 아니라 KB 매매시세 상승률이다. 세금, 거래비용, 유동성, 개인 신용 위험까지 반영한 투자수익률 모델로 설명하면 안 된다.

### 29. 현재 모델의 가장 큰 한계는 무엇인가요?

1. 60개월 검증 데이터가 충분하지 않다.
2. 최근 residual 패턴이 다음 기간에도 일부 유지된다는 가정이 있다.
3. 금리, 정책 이벤트, 대출 규제 같은 거시 변수가 ML feature에 직접 충분히 들어가 있지 않다.
4. P80/P90은 정식 확률 예측 구간이 아니라 과거 오차 기반 참고 범위다.

### 30. 다음 개선 실험은 무엇인가요?

금리·정책·시장 지표를 시간 누수 없이 추가하고, 60개월 실현값이 충분히 쌓이면 장기 horizon을 다시 검증하는 것이 우선이다. 이후 residual offset 자동 갱신, SHAP 기반 설명, conformal prediction 같은 정식 구간 예측을 검토할 수 있다.

## 답변 시 금지하거나 주의할 표현

- `1~61개월을 모두 예측한다` → 관측 기간과 horizon을 혼동한 표현
- `세 기간을 한 번에 출력한다` → 서비스는 묶어 반환하지만 모델은 기간별 호출
- `MAE 5%이므로 정확도 95%다` → 잘못된 해석
- `P80은 80% 신뢰구간이다` → 과거 test 절대오차 분위수
- `R² 0.715가 모델 신뢰도다` → 단독 신뢰도 지표가 아님
- `ver1부터 ver16까지 동일 조건에서 38.8% 개선됐다` → 38.8%는 ver9b 대비
- `ver14는 성능이 나빠서 폐기했다` → test는 개선됐지만 holdout 안정성 미통과
- `60개월 검증이 끝났다` → inference만 가능하며 low confidence
- `LightGBM ver16` → ver9b LightGBM base + ver16 residual calibration
